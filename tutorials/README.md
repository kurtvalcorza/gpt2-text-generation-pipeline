## What changed from the inference-only tutorial

The previous notebook (`TASK-INFERENCE`) continued one synthetic prompt in both decoding modes and reported a `not-measurable` verdict because the repository shipped no metric and a continuation has no ground truth. This notebook keeps that inference contract as Section 5 (on an unseen abstract's opening instead of the synthetic prompt) and adds the adaptation contract around it: a real corpus of paper abstracts, perplexity and bits per token in the carried `metrics.py` with an add-one unigram floor as the reference point, a bounded fine-tuning of the last transformer blocks, before/after continuations, and an artifact that reloads. The per-prompt `evaluation_report` still returns `not-measurable`; `pipe.evaluate` is the corpus-level stage (`measured` / `measured-small-sample`).

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's 3 modules verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports), Section 3 carries the 15-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries a fresh clone lacks (the git-ignored `model.safetensors`), at the pinned revision; `verify_snapshot` re-hashes every entry; `GPT2TextGenerationPipeline.from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files (`local_files_only=True`, `trust_remote_code=False`); no cell outside the carried modules calls `huggingface_hub`, `transformers`, `safetensors`, `urllib` or the model's own `generate`.
- **Data (DAT1–DAT9, ST6):** the default sample is three pinned objects — `train.jsonl` / `dev.jsonl` / `test.jsonl` of SciTLDR-A (3,155,015 / 1,124,865 / 1,204,107 bytes; SHA-256 `b222771d…` / `3191fa98…` / `fb42dd6c…`) from `raw.githubusercontent.com` at the pinned `allenai/scitldr` commit — each refused on any mismatch before it is parsed, reduced to the abstract text, filtered to 200..2,400 characters and de-duplicated, and drawn by a seeded shuffle into 300 / 50 / 100 records from the release's own paper-disjoint members (`check_split_disjoint` asserts it). The template adds a second *External access* bullet naming the host, the byte counts and the Apache-2.0 licence.
- **Stages (§4.1):** `fetch_corpus` + `read_corpus` + `build_sample_dataset` / `load_byod_dataset` + `split_dataset` (sample acquisition) → `validate_dataset` + `check_split_disjoint` + refusal probes (validation, with three digests) → `validate_inputs` + `validate_settings` + `pipe.generate` in both modes with sanity checks and the frozen continuations of three unseen openings (inference contract) → `pipe.unigram_baseline` + `pipe.evaluate` on the frozen model (floor and baseline) → `pipe.adapt` (bounded fine-tuning) → `pipe.evaluate` on validation and test with the comparison (evaluation) → `pipe.generate` on the unseen openings after adaptation + `evaluation_report` (inference) → `pipe.save_artifact` → `GPT2TextGenerationPipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** the pipeline emits no probability, confidence or score with a generation; perplexity and bits per token are the model's own teacher-forced likelihoods on held-out text (token-weighted, natural log, a record's first token not predicted, tokenisation-dependent), not fluency, factuality or a human judgement; no acceptance threshold ships; `finished_by == 'max_new_tokens'` is explained as a cut output and the pad/EOS quirk (`PAD_TOKEN_ID = EOS_TOKEN_ID = 50256`) is printed and explained.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the unigram floor and the frozen model are scored on the same 100 test abstracts as the adapted model, `n_tokens` is asserted equal across them, `record_perplexity` min / median / max is printed beside every corpus figure, and every metric is labelled as one seeded split of one corpus with no dispersion estimate; the notebook states that the adapter changes the shared transformer blocks and prints continuations before and after as text, not evidence.
- **Split integrity (SPL1–SPL8):** the split is seeded and text-disjoint (the release's own train/dev/test partition); validation selects the epoch and the test split is used for nothing but the final evaluation and the reload-parity check; the notebook states that documents from one collection or author must be split by that grouping.
- **Ceilings (VAL6):** `CONTEXT_LENGTH` (1,024), `MAX_PROMPT_TOKENS` (1,023, rejected not truncated — also for scored records), `MAX_NEW_TOKENS` (256), `MAX_TEXT_CHARS` (4,000), `MAX_TRAIN_TOKENS` (512, training-only truncation), the record bounds (a training split of 8..20,000 records, so at least 12 unique BYOD records with the default fractions) and the id pattern are stated in the Prerequisites and printed before the model runs; four dataset refusals and one settings refusal are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, user documents flow through the same validation, seeded text-disjoint split, floor, frozen scoring, fine-tuning, evaluation, inference, export and reload cells. The expected schema and the privacy guidance — an internal document collection is restricted data, and a base model can continue any prompt with false or offensive text — are stated in the Prerequisites and in Section 4, and the training split is written to `outputs/gpt2_text_generation_train.csv` in that shape.
- **Runtime (RUN1, RUN10, ENV6; review GPT-M1):** nothing is installed into the notebook kernel. Section 1 downloads the pinned `uv` 0.12.15 wheel (refused unless its size and SHA-256 match), creates a managed CPython 3.12.12 environment and installs the carried hash-locked `tutorials/requirements-colab.lock.txt` (compiled from the `pyproject.toml` pins for manylinux x86_64; the same lock as ast-audio-classification-pipeline 16eee39, whose pins plus `tokenizers==0.22.2` equal these) with `--require-hashes --only-binary :all:`; every later cell runs in one persistent worker in that environment, so no restart is needed. The notebook therefore supports **Linux x86_64 runtimes only**.
- **Rerun validity (DAT13, DAT14, GDL10, UX5; review GPT-M3):** Sections 4, 5, 6 and 7 each call `pipe.reset_to_pretrained()`, which restores every tensor an earlier `adapt` or `load_artifact` changed; `adapt` refuses a pipeline that already holds an adaptation; Section 7 checks that epoch 0 equals the Section 6 validation perplexity; `save_artifact` refuses to export when a block outside the adapter differs from the base; and Section 9 asserts that the report, the adapter and the form agree on `TRAINABLE_BLOCKS`. A BYOD rerun therefore measures the pretrained model and exports an adapter trained on the BYOD corpus only, and the `TRAINABLE_BLOCKS = 1` activity reloads with parity.
- **Recorded outcomes (DAT13, RUN9; review GPT-m2):** the floor and adaptation comparisons are recorded as `floor_outcome` / `adaptation_outcome` in the report and result file instead of bare assertions; the remaining assertions (reload parity, one model per export) carry messages naming the next action.
- **Pretraining overlap (DAT9; review GPT-m5):** Section 6 and the closing state that GPT-2's WebText may contain some of these abstracts, so the absolute pretrained perplexity may be optimistic; the pretrained-versus-adapted comparison stays like-for-like. The defaults were chosen with the sample test split in view, and the notebook says the delta is optimistic.
- **Guided layer (§3.5, GDL1–GDL14; review GPT-M2):** see the checklist below.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
